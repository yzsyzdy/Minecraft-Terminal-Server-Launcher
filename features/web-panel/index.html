    网页面板¶

    三种进法，随便挑一种：

    • 主菜单 [8] 网页面板 —— 双击 exe 或直接 python start.py 进去就能看到，不用记参数
    • python start.py web —— 直接起面板，默认 http://127.0.0.1:8765
    • python start.py --help —— 忘了怎么用的时候看这个

    面板子菜单里还能改监听地址 / 端口、重新生成访问 token、以及让面板随软件启动；启动后会打印一条带 token 的地址，点开即登录。

    开启「随软件启动」后，软件一起来面板就在后台线程里跑着，终端该进菜单进菜单、该起服务器起服务器，互不干扰。

    终端菜单适合人坐在机器跟前用，网页面板适合人不在跟前的时候：出门在外、手机上，或者只是不想开着那个黑窗口。

    能做什么¶

    面板围绕一个闭环：看实例 → 启动 → 实时看控制台 → 敲指令 / 停止。旁边挂着文件管理器与新建实例。

    • 看实例：列出 servers/ 下的所有实例，带版本、核心与运行状态
    • 实例详情：选中后上方一条详情栏，显示内存、PID 或退出码、Java、工作目录与拼好的启动命令
    • 启动 / 停止：停止是优雅的，先往控制台发 stop，超时才强杀
    • 实时控制台：走 SSE 推送，服务端输出逐行到达；同一条也会追加写入实例目录下的 logs/mstl-console.log
    • 敲指令：输入框里写什么就原样发给服务端进程，等价于终端里的交互模式；上方还有 list / save-all / help 一键发送，say 只管把前缀填好
    • 控制台操作：清屏、是否跟随自动滚动、WARN 与 ERROR 分开着色，向上翻看时自动暂停跟随
    • 文件管理器：按实例浏览目录树，直接编辑 server.properties 这类文本文件；新建文件/文件夹、重命名、删除、上传、下载
    • 新建实例：从 MSL 镜像下载服务端核心、用本地 jar、导入已有的服务端 zip 存档，或者建一台通用实例
    • 实例设置：改内存、额外 JVM 参数、进程优先级、随软件启动、通用实例的启动配置，以及 OpenFrp 隧道绑定
    • frp 内网穿透：在面板里配 frpc.toml、增删隧道、启停 frpc、下载 / 更新 frpc 二进制（下载不通时可手动上传）
    • 进度可见：下载服务端核心、下载 frpc、上传文件与文件夹都会在底部显示进度条——几十 MB 的核心不必再对着一个转圈的按钮干等

    控制台与文件管理器是右侧面板的两个标签页，切换标签不会中断 SSE 连接；实例设置（⚙）与 frp（顶栏 frp）是另外两个对话框。

    文件管理器¶

    选中实例后切到「文件」标签：

    • 点目录进入，点文本文件（如 server.properties、ops.json、各类 .yml）直接进编辑器，点其他文件则下载
    • 每行右侧是操作按钮：下载、编辑、重命名、删除；压缩包多一个「解压」
    • 工具栏可以回上一层、回到实例根目录、刷新、新建文件/文件夹、上传文件、上传文件夹

    上传文件夹¶

    工具栏的「上传文件夹」用浏览器的目录选择器，选中的整个目录会带着相对路径传上来：选 world 就得到 world/level.dat、world/region/…，目录结构原样保留。缺失的中间目录会一并建出来（浏览器给出的 文件顺序不保证，world/level.dat 完全可能先于 world/ 到达）。进度条显示 正在上传 12/340。

    一个浏览器限制：空目录传不上来——目录选择器根本不会报告空目录，所以它们不会被创建。

    在线解压¶

    压缩包那一行有「解压」（⇲）按钮，确认后就地解开（解到压缩包所在的目录）。支持 zip 与 tar 系（.tar / .tar.gz / .tgz），而且按内容识别，不看后缀——浏览器存下来的名字常被改过。

    • 默认不覆盖：已存在的文件跳过。解压常见于「往一个已有实例里补文件」，悄悄盖掉 server.properties 比解压失败糟糕得多。结果会如实回报跳过了几个
    • 解压出来的东西受同一套路径约束：成员名里的 ..、绝对路径、盘符一律拒绝； 压缩包里的符号链接 / 硬链接直接跳过（软链指到实例外面就等于绕过沙箱）
    • 另有两道闸挡压缩炸弹：成员数上限 20 万、解压后总体积上限 4 GiB

    路径与容量上的约束：

    • 所有路径都锁在所选实例目录内。相对路径里出现 .. 或盘符会被拒绝；目录里若有符号链接 / junction 指向实例之外，解开后同样会被拒绝。开头的 / 表示「从实例根目录算起」，不是文件系统绝对路径
    • 单文件可编辑上限 2 MB；超过上限、或内容是二进制（含 NUL 字节）、或不是 UTF-8 文本，都会拒绝编辑，请改用下载
    • 上传单文件上限 512 MB，流式写入，不占内存；上传文件夹是逐个文件走的，每个文件同样受这个上限约束
    • 写入一律「临时文件 + 原子替换」，中途失败不会把原文件截成半截
    • 不能删除实例根目录本身；删除目录会连同里面的内容一起删掉

    新建实例¶

    顶栏的 ＋ 打开对话框，四种方式各一个标签：

    下载核心——从 MSL 镜像选服务端核心（Paper、Purpur、Fabric、Forge、Velocity……）与版本。核心版本号本身就是 MC 版本号，会自动填进 MC 版本一栏，可以改。下载失败会把刚建的空目录回滚掉，不会留下一个半成品实例。

    本地 jar——选一个本地 .jar；面板先建实例（把 jar 名写进配置），再把文件传上去。如果上传失败，实例仍然保留，可以在文件管理器里补传。

    导入存档——填一个 面板所在机器上 的 zip 路径（不是从浏览器上传），先「扫描压缩包」列出里面的候选核心 jar，选一个再「导入」。扫描与落地是两步，对应 core/ 里的 plan_import / commit_import；界面层负责在候选多于一个时问用户。

    通用实例——见下一节。它不跑 Minecraft，跑你自己指定的程序或命令。

    实例名的校验：不能为空、不超过 64 字符、不含 \ / : * ? " < > |、不能是 Windows 保留设备名（con、nul 之类）。重名会直接报错，而不是悄悄改名成 name_1——名字是你指定的，改了你就找不到自己的实例了。

    通用实例¶

    除了 Minecraft 服务端，MSTL 还能把任意一个长期运行的程序或命令当成实例来管：一样有启停、实时控制台、写日志、发指令、随实例自动开隧道，只是启动时不做 Java 解析、也不校验 jar。命令行菜单里同样有入口（主菜单 [3] 新建实例）。

    实例的 kind 只有两种：minecraft（默认，走原来的 Java + jar 流程）和 generic。.server.json 里的 launch 段描述通用实例怎么启动：

    启动方式 行为
    exec 直接运行 program（可执行文件），参数来自 args 数组，不经 shell——所以 &&、管道不会被解释
    cmd cmd.exe /c "<command>"，整段交给 cmd 解释，管道、重定向、&& 都能用
    powershell powershell -NoProfile -ExecutionPolicy Bypass -Command "<command>"（非 Windows 用 pwsh）

    program 支持相对路径（相对实例目录）与绝对路径；workdir 是工作目录，相对路径同样按实例目录算，留空即实例目录。

    几个实际用法：把一个自建的 Python / BAT 服务脚本挂进来；用 cmd 模式跑 java -jar xxx.jar 之类的自定义启动行；用 powershell 模式跑一段探针或定时任务。

    注意信任边界：走 cmd / powershell 时，配置里的字符串会原样交给 shell 解释——这是功能本身的要求。它的信任边界和「面板能发控制台指令」「面板能改 .server.json」是同一条：能改这个配置的人，本来就已经能在这台机器上跑东西了。

    改启动配置有两个入口：面板里选中实例后点标题栏的 ⚙，或者在文件管理器里直接编辑 .server.json（改完下次启动生效）。实例的 kind 在创建后不可更改——切换种类等于把实例换成另一个东西，不该混在「保存设置」里悄悄发生。

    frp 内网穿透¶

    顶栏的 frp 按钮打开隧道面板，对应 frp/frpc.toml：

    • 状态：frpc 是否在运行、二进制是否已下载
    • 连接设置：serverAddr / serverPort / auth.token，保存后写回 frpc.toml
    • 启停：启动 / 停止 frpc，和命令行菜单里操作的是同一个进程
    • 下载 / 更新 frpc：从镜像或 GitHub Releases 取二进制。下载不通时不用干瞪眼：面板会把 GitHub 发布页地址摆出来，并给一个「上传 frpc」按钮——自己下好压缩包（或者解出来的 frpc / frpc.exe）直接传上来即可，压缩包会自动解出里面的二进制
    • 隧道列表：每条隧道显示名称、类型、本地地址与端口、远程端口或域名，可逐条删除
    • 添加隧道：tcp / udp 填远程端口，http / https 填域名（逗号分隔）

    面板只改上面这几个键，frpc.toml 里其它内容读进来会原样保留，写回去不会丢——包括 [[visitors]] 这类别的「表的数组」，与命令行菜单是同一套读写实现。唯一的例外是注释：这套极简 TOML 读写不保留注释，保存一次就会被去掉。

    上传的兜底路径按内容判断，不看文件名（浏览器存下来的名字常被改过）：zip / tar.gz 解出里面的 frpc，裸二进制直接收下。但它会检查解出来/传上来的东西像不像本平台的可执行文件——拿错平台的包（比如在 Windows 上下了 linux 的 tar.gz）会当场拒掉并清掉半成品，而不是装上一个一跑就报格式错误的 frpc.exe。

    面板管的是原版 frp。OpenFrp 那种云端隧道走的是另一套 API，面板只参与「实例绑定」那一小步：在实例设置里填用户 token 与隧道 ID，并决定要不要随实例自动开启。

    登录¶

    首次运行会随机生成一个 token，写进 config.json 的 web.token，并在启动时把带 token 的地址打印出来：

    网页面板已启动: http://127.0.0.1:8765/?token=xxxxxxxx
访问 token: xxxxxxxxxxxxxxxx

    用它打开一次，token 会存进 cookie，之后直接访问 http://127.0.0.1:8765/ 即可。校验用定长比较，并且只认 mstl_token 这个 cookie 本身的值。

    出示 token 的三条通道（X-MSTL-Token 请求头、mstl_token cookie、?token= 查询参数）是并列的：命中任意一条就放行。这样浏览器里留着旧 token 的 cookie 时，地址栏里那个正确的新 token 依然有效，并且会用新 token 把旧 cookie 覆盖掉。

    在菜单里「重新生成访问 token」之后，正在运行的面板会立刻认新 token，不需要重启；菜单会把新地址直接打印出来。

    提示「访问 token 无效或缺失」¶

    先按这个顺序排查：

    1. 旧 cookie 挡路：浏览器里可能还留着上一个 token 的 cookie。按 Ctrl+F5 强制刷新，或清掉本站 cookie，再点菜单打印出的完整地址。
    2. 127.0.0.1 与 localhost：浏览器认为这是两个站点，cookie 不通用。刚才用哪个开的就一直用哪个。
    3. 刚换过 token：用菜单里新打印的地址，旧地址里的 token 已经失效。

    401 页面上也写着这三条。

    安全边界¶

    面板里能往服务端控制台发指令、能改实例目录里的文件、还能把实例配成「执行任意命令」，等于把实例目录和一条命令通道一起交给了浏览器。 守护进程跑在你的用户身份下，浏览器点一下就能 stop、改 op、改 server.properties、删文件、让一个通用实例去跑任意命令。所以：

    • 默认只监听 127.0.0.1，本机之外访问不到
    • 所有 /api 都要求 token
    • 要经 frp 穿到公网，请在前面加一层反向代理与 HTTPS，别让面板裸奔。改 web.host 之前先想清楚这一点
    • 拿到 token 就等于拿到实例目录的读写权限与这条命令通道；没有开关能把文件管理器或通用实例单独关掉

    配置¶

    字段 默认值 说明
    web.host "127.0.0.1" 监听地址，0.0.0.0 表示所有网卡
    web.port 8765 监听端口；填 0 表示随便挑一个空闲端口
    web.token "" 访问 token，留空则首次启动自动生成
    web.auto_start false 面板随软件启动。后台线程运行，不阻塞终端菜单；在面板子菜单 [4] 里开关

    关于 8765 端口

    8765 也是 VS Code 的 Python 调试器（debugpy）默认端口。若正在调试 Python 时启动面板，两者会抢同一个端口；Windows 上旧版本会因为 SO_REUSEADDR 静默「抢成功」，表现为面板偶发 401 或打不开。现在 Windows 上已关掉该选项，冲突会直接报「无法监听」。换端口即可。

    命令行参数可以临时覆盖 host 与 port：

    python start.py web --host 0.0.0.0 --port 9000

    接口一览¶

    面板前后端之间的全部约定：

    方法 路径 说明
    GET /api/state 实例列表 + 当前语言的一批界面文案
    GET /api/stream SSE 事件流，一次订阅全部实例；带 ?name=<实例> 可只看一台
    POST /api/start 体为 {"name": "..."}
    POST /api/stop 体为 {"name": "..."}
    POST /api/command 体为 {"name": "...", "command": "..."}
    GET /api/files ?name=<实例>&path=<相对路径>，列目录
    GET /api/file ?name=&path=，读文本文件
    GET /api/file/raw ?name=&path=，下载原始字节
    POST /api/file/write {"name": "...", "path": "...", "content": "..."}
    POST /api/file/mkdir {"name": "...", "path": "..."}
    POST /api/file/rename {"name": "...", "path": "...", "new_name": "..."}
    POST /api/file/delete {"name": "...", "path": "..."}
    POST /api/file/extract {"name": "...", "path": "...", "dest"?, "overwrite"?}，就地解压一个压缩包
    POST /api/file/upload ?name=&path=，请求体就是文件内容，按 Content-Length 精确读取
    GET /api/cores 服务端核心列表；带 ?type=<核心> 返回该核心的版本列表
    POST /api/instances {"name", "kind"?, "mc_version", "min_mem", "max_mem", "core_type"?, "core_version"?, "jar_name"?, "launch"?}
    POST /api/instances/settings 改实例设置：{"name", "min_mem"?, "extra_jvm_args"?, "launch"?, "openfrp"?, "auto_start"?, ...}；kind 与 name 不可改
    POST /api/instances/import/scan {"zip_path": "..."}，返回候选核心
    POST /api/instances/import/commit {"zip_path": "...", "jar": "...", "name": "..."}
    POST /api/instances/import/abort {"zip_path": "..."}，丢弃解压出来的临时目录
    GET /api/frp frpc 状态 + 连接设置 + 隧道列表
    POST /api/frp/settings {"serverAddr", "serverPort", "token"}
    POST /api/frp/proxy 添加隧道：{"name", "type", "localIP", "localPort", "remotePort"?\|"customDomains"?}
    POST /api/frp/proxy/delete {"index": 0}
    POST /api/frp/start 启动 frpc
    POST /api/frp/stop 停止 frpc
    POST /api/frp/download 下载 / 更新 frpc 二进制

    约定：

    • 失败一律回 {"ok": false, "key": "<i18n key>", "message": "<当前语言的说明>"}，HTTP 400；没预料到的异常回 500，前端统一把 message 弹出来
    • SSE 事件有三种：{"type": "line", ...} 是控制台的一行，{"type": "state", ...} 是状态变化，{"type": "job", ...} 是长任务进度（带 label / ratio / done）。line 与 state 带 instance 字段标明来自哪个实例，还带一个实例内单调递增的 seq——断线重连时服务端会把历史整段重放，前端靠 seq 把画过的行筛掉，不会出现重复；job 不属于任何实例，因此也不参与按实例过滤
    • 带 kind: "note" 的行由 MSTL 自己产生，服务端已经翻好文案再推出去
    • 下载类的 POST 是同步的，进度靠上面那条 SSE 推；上传由浏览器直接报进度（XMLHttpRequest.upload.onprogress），服务端不参与

    已知边界¶

    这一版是闭环加几个常用面板，不是完整的运维面板。还没做的：插件与模组管理、重启后恢复「上次在跑哪些服」、在面板里管理 OpenFrp 云端隧道（建/删隧道仍要走命令行菜单）。

    文件管理器也刻意留了边界：一次只操作一个文件（没有批量选择、多选删除），空目录传不上来（浏览器的目录选择器不报告空目录），解压只认 zip 与 tar 系（7z / rar 需要外部程序），不显示磁盘占用，也没有断点续传。

    真要补齐，它们都会顺着同一套 core/ 接口接进来。
